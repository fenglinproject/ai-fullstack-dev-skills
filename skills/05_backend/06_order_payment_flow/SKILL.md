## 10. 订单支付流程硬性检查清单

凡是涉及订单、支付、退款、余额、积分、库存、优惠券、预约扣费，本 Skill 必须额外输出以下内容，不能只给 CRUD：

### 10.1 状态机

| 状态机 | 必须包含 |
|---|---|
| 订单状态机 | 待支付、已支付、已取消、已关闭、已完成、退款中、已退款、异常 |
| 支付单状态机 | 待支付、支付成功、支付失败、已关闭、退款中、已退款、回调异常 |
| 退款状态机 | 申请中、退款处理中、退款成功、退款失败、人工处理 |

### 10.2 支付安全与一致性

- [ ] 回调必须验签，不能只信任前端支付结果。
- [ ] 必须校验商户号、订单号、支付单号、金额、币种、支付状态。
- [ ] 回调必须幂等，重复回调不能重复发货、重复记账、重复加积分。
- [ ] 支付状态变更必须在数据库事务内完成。
- [ ] 金额字段使用整数分或 DECIMAL，禁止使用浮点数。
- [ ] 超时未支付订单必须有关闭策略。
- [ ] 支付成功后异步动作必须可补偿。
- [ ] 必须记录第三方交易号、回调摘要、处理结果和异常原因。

### 10.3 必须输出的测试用例

| 场景 | 预期 |
|---|---|
| 正常支付成功 | 订单和支付单状态一致 |
| 重复支付回调 | 只处理一次 |
| 回调金额不一致 | 拒绝处理并记录告警 |
| 回调签名错误 | 拒绝处理 |
| 用户取消支付 | 订单保持待支付或关闭 |
| 超时未支付 | 订单自动关闭 |
| 支付成功后业务动作失败 | 进入补偿或人工处理 |
| 退款成功 | 订单、支付单、退款单状态一致 |
